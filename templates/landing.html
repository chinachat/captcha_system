// 02 — ARCHITECTURE

轻如命令行，稳如生产服务

单个进程承载全部能力：验证码生成 / 行为校验 / 统计 / 管理 API。可选组件按需启用。

▌
HTTP

http.server 线程化服务 — 连接上限 + 请求体上限 + keep-alive 复用连接，前端响应更快

DB

SQLite 开箱即用，设置 DATABASE_URL 一键切换 PostgreSQL（自动建表迁移）

CACHE

可选 Redis — Token 自动过期、多实例共享限流与失败锁定，无 Redis 自动回退内存

AUTH

JWT 固定算法 + 双角色（管理员/普通用户）、TOTP 二次验证扫码绑定、API Key 隔离

// 03 — SECURITY

每一层都在拒绝机器人

纵深防御：从边缘限流到凭证校验，九道防线。左侧为真实拦截日志（示例），每一次攻击都会被记录并拒绝。

ATTACK LOG :: liveREC
L1 边缘

IP 限流 · 按 action 独立配额 — 生成/登录/注册各自限流，429 带 retry_after 退避

L2 接口

失败锁定 + 登录验证码 — IP + Key 双维度失败锁定；后台登录需图片验证码防暴力破解

L3 行为

轨迹 / 时序校验 + jti 一次性 — 线性滑动、缺失轨迹、点击过速均判异常；pass_token 重放即拒

L4 凭证

TOTP 二次验证 + PBKDF2 哈希 — 扫码绑定两步登录；密码哈希存储，空凭据 fail-fast 拒启

L5 生态

WordPress 插件四类表单防护 — 登录 / 注册 / 评论 / 找回密码，开箱即用

// 04 — DEPLOY

一条命令，跑起来

镜像发布在 GitHub Container Registry，多架构 amd64 / arm64，无需 clone 仓库、无需本地构建。

# 拉取编排文件与配置模板
curl -O https://raw.githubusercontent.com/chinachat/captcha_system/main/docker-compose.yml
curl -O https://raw.githubusercontent.com/chinachat/captcha_system/main/.env.example

# 配置生产凭据（.env 不入库）
cp .env.example .env  # 填写 SECRET_KEY / ADMIN_PASS / DEFAULT_API_KEY

# 启动（自动拉取 ghcr.io/chinachat/captcha_system）
docker compose up -d captcha
docker compose logs -f captcha

# 升级
docker compose pull && docker compose up -d
